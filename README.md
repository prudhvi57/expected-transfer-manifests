# Expected Transfer Manifests (ETM)

Detect missing files and missing business acknowledgments in scheduled
managed file transfer (MFT) and EDI flows, using metadata only.

An Expected Transfer Manifest describes what should arrive, when, and which
business ACK must follow. A monitor compares that manifest with transfer
metadata (no payloads, no filenames) and reports `MISSING_FILE`, `LATE_FILE`,
`MISSING_ACK` and `LATE_ACK`. A transport receipt never counts as a business ACK.

Author: Prudhvi Raj Katragadda. Companion code for the paper
"Expected Transfer Manifests for Scheduled Enterprise Data Transfers:
A Review and Reference Architecture".

Python 3.11+ and the standard library are enough. `jsonschema` is only needed for
optional schema validation (`pip install -r requirements-dev.txt`).

## Quick start

```sh
python -m unittest discover -s tests -v
python monitor.py --config examples/feeds.json --events examples/events.jsonl \
  --start 2026-10-01 --end 2026-10-31 --now 2026-10-15T01:00:00Z
```

The example exits 1 with `MISSING_ACK`: the partner's system received the file,
but no business confirmation arrived. Exit codes are 0 (no findings),
1 (findings) and 2 (invalid input). The monitor only prints JSON.

## Reproduce the results

```sh
python paper-experiment/check.py      # paper results: 556 of 563 faults alerted
python verify.py                      # conformance benchmark, byte for byte
```

Paper experiment, five seeds: ETM alerted 556 of 563 injected faults and reported
the other 7 as monitoring gaps during a collector outage. False alerts were
11,623 for a static UTC rule baseline, 802 for a static local time baseline and
111 for ETM. See [paper-experiment/README.md](paper-experiment/README.md).

Conformance benchmark: the reference monitor matches all 420 labels, versus
0.500 exact match for a transfer-only check and 0.786 for one that accepts any
receipt as an ACK. The cases were written together with the spec, so this shows
the rules behave as specified, not accuracy on real traffic.

## Scope

All data in this repository are synthetic and generated by the scripts here.
It contains no employer systems, partner data or production logs, and no
adapters for commercial MFT products. Parts of the code and documentation were
written with AI assistance and reviewed by the author.
